## 对照与改动

| 路径 | WorkBuddy 行为 | CodeArts 本次调整 |
| --- | --- | --- |
| 绑定号满载 | 解绑并轮换到空闲号 | 默认优先等 1 秒，再有空闲号则迁移；`CODEARTS_STICKY_WAIT_MS=0` 可立即迁移 |
| 每号在途 | 在途名额跨模型共享，释放跟随整次流 | 保持现有完整流名额管理、原子占用和幂等释放；等待名额共享本次请求的截止预算 |
| 会话识别 | 显式会话 ID 优先，不把用户 ID 当会话 | 增加 `conversation_id` / `session_id` 请求头，稳定会话头优先于滚动缓存键，按调用方隔离 |
| 缓存与任务身份 | 会话、轮次、任务分别标识，换号按实际账号生成 | 修复每次推理都更换正文缓存键的问题；会话+账号决定缓存键，任务头与查询 ID 按请求生成 |
| 模型限流轮换 | 不消耗普通故障重试上限 | 排队、限流和模型额度错误可继续尝试未用账号，普通故障最多尝试 3 个 |
| 模型冷却 | 只冷却该账号的该模型，重复失败不延长 | 复用上游模型限流表；按用户要求统一随机 60–180 秒，启动时缩短旧长冷却 |
| 手动恢复 | 批量解除冷却 | 模型面板勾选批量解除或解除全部；保留账号启用与模型开关 |
| 流与取消 | 边读边写，写入阻塞传回读取端 | 外层继续用 Node 流管道，内层拉取 CodeArts 内容前等待 SSE `drain`，断连可中断等待 |
| 成功绑定 | 成功后确认绑定，取消不当作成功 | 预留临时绑定以合并同会话并发；首次请求取消且没有其他活动请求时移除，已有成功绑定保留 |

参考文件：`internal/server/handler.go`、`internal/pool/cooldown.go`、`internal/session/session.go`、
`internal/session/ids.go`。没有复制 WorkBuddy 的供应商私有业务码、额度领取、图片协议或 Redis 实现。

## 真实缓存验证

独立临时状态目录、真实宿主/网关/适配器/华为签名，使用尚未过期的临时凭据，不触发账号续期。
模型 `codearts/deepseek-v4.1-flash`，流式 `/v1/responses`，合成重复文本，固定 `session_id`，
客户端 `prompt_cache_key` 每次分别传 `turn-cache-0/1/2`。三次使用同一个账号。

| 请求 | 输入 token | 明确上报的缓存 token | 正文首字 | 总耗时 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 13,420 | 未上报 | 1.543 秒 | 3.844 秒 |
| 1 | 13,420 | 未上报 | 1.550 秒 | 4.002 秒 |
| 2 | 13,420 | 13,312（99.2%） | 1.055 秒 | 3.412 秒 |

三次实际出站正文的缓存键保持一致，`Session-Id` 任务头各异。本地获取名额耗时分别为 1、0、0 毫秒。
前两次的缓存量未知，不能当作明确零命中；本组不是隔离其他变量的性能对照，不能仅凭耗时差推断收益幅度。

## 如何理解用户提供的日志

- 本项目原生账本首字包含推理内容，不只计算最终正文；外层面板可能采用不同口径。
- 原生账本时间戳是请求结束时刻，不能通过相邻行直接推断同号同时起了几次请求。
- 原生速率用输出 token 除以“总耗时减首字”。例如总处理 398.52K、首字 85.69 秒、耗时 85.89 秒、243.9 tok/s，
  对应约 49 个输出 token；398.52K 主要来自输入和缓存，不能当作输出量。
- “未归属、15 秒失败”与默认等待名额超时一致，但仍要结合错误明细确认。
- 85–103 秒的长首字需要按输入/缓存/输出 token，以及 debug 的 `dispatchMs`、`acquireMs`、
  `firstChunkMs`、`firstTextMs` 拆开定位。本次发现的缓存键错误会破坏跨轮缓存，但现有日志不足以把所有慢请求归因于它。
