# codearts2api

把 [`dsh-providers-hub`](https://github.com/iJetLi/dsh-providers-hub) 的
**Jet Hub 多渠道账号管理**与**本机 OpenAI 网关**搬到独立后端运行，**不依赖 DSH 宿主**，
面向自建服务与容器部署。

它不 fork 上游代码，而是直接把上游的插件装载起来 —— 所以**渠道、模型、协议、界面
都跟着上游走**，本项目自己负责鉴权、状态隔离、并发调度与对外接口。

## 使用方法

### Docker 部署

推荐用镜像跑。`CODEARTS2API_HOME=/data` 已由镜像设好并声明为 `VOLUME`，**不挂卷则容器
重建后账号会丢**。

```bash
docker pull ghcr.io/zhuweiyou/codearts2api:latest
docker run -d --name codearts2api \
  -p 8080:8080 \
  -v codearts2api-data:/data \
  ghcr.io/zhuweiyou/codearts2api:latest
```

也可以在仓库根目录自行构建：`docker build -t codearts2api .`，再把上面的镜像名换成
`codearts2api` 运行。

首次启动会在 `/data/admin-key` 生成管理密钥，用它登录后台：

```bash
docker exec codearts2api cat /data/admin-key
```

打开 `http://<主机>:8080/admin` 进入。管理接口自带鉴权，`-p 8080:8080` 不会把后台直接
暴露给公网；公网部署仍需自行终结 TLS（见 [`AGENTS.md`](AGENTS.md)）。

### 本机直跑

**要求**：Node.js `^22.19.0 || ^24.11.0 || >=26.0.0`（建议 24 LTS ≥24.11），包管理器用 **pnpm 11**
（`corepack enable` 即可；项目已含 `pnpm-lock.yaml`）。

```bash
pnpm install
pnpm run build   # 前端(dist/) + 后端(dist-server/) 一起构建
pnpm start       # 运行后端编译产物 dist-server/index.js
```

启动后打开 <http://127.0.0.1:8080/admin>。首次启动会在日志里打印一次管理密钥
（默认状态目录 `~/.codearts2api`，可用 `CODEARTS2API_HOME` 指定），用它在登录页进入后台。

### 管理界面

`/admin`（登录后）顶栏是三个一级页面：

- **总览**（默认首页）：网关状态、今日用量、近 14 日趋势、渠道账号与余额、积分收支、
  模型分布、自动签到；
- **渠道管理**：上游 Jet Hub 设置页原样复用 —— 左侧为各渠道，页头「网关」按钮可查看
  对外地址、复制 API Key 与模型清单；
- **调用方**：多把 Key 与分组授权（见下）。

顶栏右侧还有 **「回调修复」**（远程部署时第三方登录跳回 `127.0.0.1` 打不开，可让服务器
本机重放）与**主题切换**（跟随系统 / 浅色 / 深色）。

### CodeArts JSON 导入与导出

打开「渠道管理」，点顶部 **「导入 CodeArts JSON」**，选择一个或多个 `.json` 文件。
每个文件可以是一个账号对象，也可以是账号对象数组。每批最多 100 个文件，总大小不超过 2 MB。
检查预览后点 **「确认导入」**；格式错误的记录会列出原因，其余有效记录仍可导入。

必需字段为 `access_key_id`、`secret_access_key`、`cloud_dragon_token`、`expiration`。
同时兼容上游标准字段，转换关系如下：

| 文件字段 | 上游凭据字段 |
| --- | --- |
| `cloud_dragon_token` | `security_token` |
| `expiration` | `expires_at` |
| `dpop_private_key` | `dpop_private_key_jwk` |

`user_id`、`user_name`、`domain_id` 会保留；账号名优先取 `user_name`。
自动续期需要同时提供 `refresh_token`、`code_verifier` 和 EC P-256 格式的 DPoP 私钥（含 `x/y/d`）。
临时凭据已经过期也可以导入，但能否续期取决于这些材料是否仍有效；失败时需要重新登录。

此入口只追加账号，重复导入同一文件会跳过，不覆盖已有账号、模型开关和锁定设置。
不同工具导出的同一账号若缺少一致的身份字段，上游可能无法判重，需检查是否出现重复账号。
导入成功后账号视图自动刷新。Loomy 可用下述 TXT 入口，其他渠道和完整备份仍使用上游的「备份与恢复」入口。

点同一处的 **「导出 CodeArts JSON」**，下载全部 CodeArts 账号的 JSON 数组（含停用账号），
可用上述导入入口再次导入。导出读取服务器当前保存的凭据，包含最新存储的 AK/SK、令牌、
过期时间、`refresh_token`、`code_verifier` 和 DPoP 私钥，不包含其他渠道或模型设置。
个别凭据缺失或损坏会跳过并显示数量。导出不会强制续期；原实例再次续期后，旧文件中的刷新令牌可能失效。

### CodeArts 会话粘性与并发

CodeArts 现在优先复用会话绑定的账号；新会话按在途请求数、绑定数和最近使用顺序分散。
账号禁用、凭据不可读或目标模型限额时会重新分配；绑定账号满载时优先等 1 秒，仍满载且有其他
空闲账号则迁移，避免有空闲号却一直排队。名额覆盖完整推理过程，包括 SSE 输出；完成、失败、换号、
客户端取消与超时都会回收。读取凭据、模型目录和后台续期不占用推理名额。

华为还统计请求结束后仍未释放的会话：本地在途归零不代表上游容量已恢复。调度会在发送前预留账号级
会话名额，建流后继续保留窗口占位，满窗口时立即尝试其他账号，不受模型切换影响；明确的 HTTP 拒绝回滚
占位，发送后断连或超时则保守保留。全部名额已占用且已知释放时间晚于等待预算时，立即报出预计重试时间。
正常成功请求的占位到“发出后 60 秒”和“流结束”两者中的较晚时刻；长流结束不会再额外加一分钟。

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `CODEARTS_MAX_IN_FLIGHT` | `3` | 每个账号同时进行的最大推理数，范围 1–100；跨模型、跨调用方共享 |
| `CODEARTS_SESSION_LIMIT` | `3` | 每账号上游会话占位上限，含在途与窗口内已结束请求；付费套餐确认容量后可与在途上限一起设为 5 |
| `CODEARTS_SESSION_TTL_MS` | `60000` | 从实际发送起的会话最短保留窗口，在途期间不提前释放；`0` 关闭窗口保护，仅用于诊断 |
| `CODEARTS_QUEUE_LIMIT` | `100` | 等待名额的请求上限；`0` 表示满载立即拒绝 |
| `CODEARTS_QUEUE_TIMEOUT_MS` | `15000` | 同一请求等待名额的截止预算，换号不重新获得完整等待窗口，毫秒 |
| `CODEARTS_STICKY_TTL_MS` | `1800000` | 会话绑定的空闲过期时间，默认 30 分钟，活动请求期间保留绑定 |
| `CODEARTS_STICKY_WAIT_MS` | `1000` | 绑定账号满载时优先等待多久再考虑空闲号，范围 0–120000 毫秒；`0` 表示立即迁移 |

默认每号 3 个在途、3 个会话占位，10 个空闲账号可承接一次 30 请求突发；持续处理能力还受会话释放窗口限制。
未在界面保存的项目使用环境变量；界面保存值优先。只提高在途上限不会绕过会话窗口。
实际容量还取决于 CodeArts 的模型额度和同账号其他客户端。
排队超时或队列已满时，非流式返回 HTTP 429；已经开始 SSE 响应时以错误事件返回。

Chat Completions 和 Responses 都支持显式会话键，按以下顺序读取：
`metadata.conversation_id`、`metadata.conversationId`、顶层 `conversation_id` / `conversationId`、
请求头 `conversation_id`、`session_id`、`X-Conversation-Id`、`X-Session-Id`、`X-Claude-Code-Session-Id`，
最后读取 `prompt_cache_key`。稳定的会话头优先于可能逐轮变化的缓存键，兼容 sub2api 转发。
缺省时用 system / instructions 与首条 user 内容的摘要派生。不同对话若首轮内容相同，
派生键可能相同，因此需要严格区分会话时请传显式键；`user_id` 不作为会话键。
会话键按调用方隔离，只在内存里保存摘要，不保存提示词或密钥。
超过 16 MB 的正文不额外解析会话信息，此时请使用会话请求头。

上游 `Chat-Id` 和正文中的 `prompt_cache_key` 随会话和实际账号保持稳定，`Session-Id` 请求头与
队列查询的 `task_id` 按推理请求隔离，防止并发任务共用任务 ID，同时保留跨轮缓存。
换号后重新生成该账号的请求体与签名。普通账号/传输故障最多尝试 3 个账号；模型排队、限流和额度错误
可继续尝试池内未用的可用账号。
开始输出内容块后不再跨账号重放。按需续期刷新实际选中的账号。
上游 SSE 已分类为排队，或队列端点确认 `waiting` / `queue_full` 时，不再持有名额静默等待
10 秒重试；将该账号的当前模型冷却随机 60–180 秒，输出前尝试其他账号。全部排队时返回 429（已开始 SSE
则返回错误事件）。华为 HTTP 或 SSE 的 `TM.00001041` 属于账号级会话容量，单独避让整个账号约 60 秒，
不再误写为单个模型冷却，即使队列接口返回 `working` 也换号；普通参数和鉴权错误仍交给上游处理。
冷却中的排队账号不会被误报为凭据缺失。
输出后遇到排队或额度错误也不会内部重放。

CodeArts 的本地模型冷却默认采用随机 **1–3 分钟**，重复失败不延长期限；启动时将既有的长冷却缩短到
这个范围。这是本地重新探测间隔，不表示华为真实配额已恢复；官方另有按用户和模型计算的 token/请求次数
5 小时、7 天滑动窗口。渠道管理 → CodeArts → 可用模型，可勾选后 **「解除所选冷却」**，或 **「解除全部冷却」**，
立即清除池内对应模型的本地冷却；账号启用状态与模型开关不变。操作不会恢复华为端已经耗尽的额度，
再次请求仍可能触限并重新进入冷却。
解除模型冷却不会清空仍存活的账号会话占位。

流式响应边读边转发；慢客户端产生背压时暂停拉取 CodeArts 内容，断连会中断等待并释放名额。

两账号的真实测试中，旧行为复现了 63–64 秒首字；修复后同类触限请求约 1.18 秒即返回错误。
每号上限设为 2 时，4 个短请求并发全部成功，正文首字 0.755–1.126 秒。
这是小规模短请求结果，完整条件与限制见 [实测记录](docs/codearts-latency-2026-11-18.md)。
另一次约 1.34 万输入 token 的真实测试，在滚动客户端缓存键、固定会话头的情况下，第三次请求明确报告
13,312 / 13,420 token 缓存命中（99.2%）。WorkBuddy 对照与指标解释见
[调度与缓存核对记录](docs/codearts-scheduling-review-2026-11-18.md)。

设置 `LOG_LEVEL=debug` 后，`[codearts-scheduling]` 记录从请求进入到派发、获取名额（含凭据读取）、
首个内容块、正文首字和结束的毫秒耗时，以及尝试数与账号摘要。日志不含提示词、密钥和原始账号 ID。
`firstChunkMs` 很小而 `firstTextMs` 接近 `totalMs`，可能是推理先输出、正文最后补出，不能只按正文首字判断排队。

该机制覆盖 `/v1/chat/completions`、`/v1/responses`、直接访问插件网关和聚合派发到 CodeArts 的请求。
`GET /healthz` 的 `scheduling.codearts` 可查看在途数、排队数、绑定数与生效配置。
`retainedSessions` 是已结束但仍保留的会话占位数，`accountBackoffs` 是上游并发限制触发的整号避让数。
绑定和计数属于单进程，重启后重新分配；多个实例不共享并发名额。
Loomy 复用下述调度机制，其余渠道继续使用上游原有规则。

10 账号的华为策略核对、实测及持续 200 并发的容量公式见
[会话窗口与容量实测](docs/codearts-capacity-2026-11-19.md)。一次突发与持续并发所需账号数不同。
按样本平均耗时约 10.27 秒、体验版每号 3 个会话和 60 秒窗口估算，持续 200 并发理论约需 390 个账号；
按 80% 利用率预留容量约需 488 个，可先按 500 个预算，仍需核对模型长窗口额度并做持续压测。

### Loomy TXT 批量导入与调度

「渠道管理」顶部点 **「导入 Loomy TXT」**，选择一个或多个 `.txt` 文件，每行一个账号：

```text
13800000001----aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa1----222222222222222221
13800000002----aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa2----222222222222222222
```

三列依次为手机号、32 位十六进制 session token、userid，用四个减号 `----` 分隔。
支持空行、CRLF 与 UTF-8 BOM；每批最多 100 个文件、总计 2 MB。
先预览有效、重复和错误行，再确认追加导入；不覆盖既有账号或模型设置。
预览隐藏 token 并遮盖手机号。TXT 没有到期时间，导入不会重新计算有效期；Loomy 无自动续期端点，失效后需重新登录。

Loomy 与 CodeArts 共用会话识别、调用方隔离、在途限制、有界队列、输出前换号、流式背压和取消处理。
同会话优先复用账号，`prompt_cache_key` 随会话及实际账号保持稳定；换号重新生成缓存键。
默认按在途数和会话绑定分散账号，不再按每日/永久积分档位排序；保留永久积分锁定与严格手动顺序。
余额由上游已有后台任务每 60 秒异步刷新到共享缓存；推理请求只读取现有缓存，不查询、不等待余额端点。
缓存确认无可用积分的账号会被跳过；缓存未知且允许永久积分时可尝试上游，实际额度错误仍自动换号。
永久积分锁定时，缓存无法确认每日余额会立即返回 503，不触发余额查询。
模型目录按账号分别读取并缓存，展示各账号目录的并集；DeepSeek 请求只派发给提供该模型的账号。
Loomy 的上游 ID 区分大小写：`deepseek-v4.1-flash` 等大小写别名会转换成账号目录中的 `DeepSeek-V4.1-Flash`。
已知账号均不支持时返回 404，目录无法确认时返回 503，不把未知模型交给上游静默回退成 Spark。
目录沿用上游 20 分钟缓存，查询失败短缓存 15 秒；更换 token、手动刷新或增删账号会更新对应权限。
整个账号池的目录查询共享 10 秒总预算，并发加载复用同一轮；不会按账号批次逐个累加 10 秒。
`DSH_LOOMY_FIRST_TOKEN_TIMEOUT_MS` 同时约束等待上游响应头（默认 120 秒），超时输出前自动换号；响应头到达后解除该计时，长流沿用原有 SSE 超时。

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `LOOMY_MAX_IN_FLIGHT` | `2` | 每账号同时进行的推理数，跨模型与调用方共享，范围 1–100 |
| `LOOMY_QUEUE_LIMIT` | `100` | 等待请求数上限；`0` 表示满载立即拒绝 |
| `LOOMY_QUEUE_TIMEOUT_MS` | `15000` | 获取名额的总等待预算，换号不重置，毫秒 |
| `LOOMY_STICKY_TTL_MS` | `1800000` | 会话绑定的空闲有效期，毫秒 |
| `LOOMY_STICKY_WAIT_MS` | `1000` | 绑定账号忙时优先等待时间，毫秒 |

这些配置独立于 `CODEARTS_*`，也可通过下述界面立即修改。Loomy 完成或取消后立即释放本地名额，没有附加的华为 60 秒会话窗口。
HTTP 429 限流默认随机冷却当前账号模型 60–180 秒，重复失败不延长；明确的积分耗尽仍按上游规则冷却到 UTC+8 次日零点。
HTTP 401/403 或 HTTP 200 内业务码 `100002` 会短暂避让该账号，输出前尝试其他账号；普通故障最多 3 次，限流/额度错误可遍历未用账号。
已输出内容后不跨账号重放。模型面板支持 **「解除所选冷却」** 与 **「解除全部冷却」**，解除只清本地标记，不恢复服务端积分。

`/healthz` 的 `scheduling.loomy` 查看生效配置与计数；`LOG_LEVEL=debug` 输出 `[loomy-scheduling]` 分阶段耗时和账号摘要。
18 个有效账号的完整网关测试中，24 并发全部成功，正文首字 P50 6.53 秒；稳定会话的重复请求明确报告约 99.2% 缓存命中。
上游仍有长尾等待，默认 2 是保守起点，尚未验证持续 200 并发。方法、对比与限制见 [Loomy 实测记录](docs/loomy-scheduling-2026-11-19.md)。
大小写回退、账号权限与完整链路对比见 [Loomy 链路排查](docs/loomy-chain-2026-11-19.md)。

### 界面修改调度配置

打开「渠道管理」→ **「调度设置」**，选择 CodeArts 或 Loomy，修改后点 **「保存并立即生效」**，无需重启。
未修改时默认分别为每账号 3 / 2 个在途；各账号独立计数，同一账号的不同模型、调用方共用该账号名额。
界面支持在途、队列、等待超时、粘性等待与绑定有效期、随机模型冷却上下限（默认 60–180 秒）；
CodeArts 另可配置会话占位上限和保留窗口。其他渠道继续沿用上游规则。

提高在途上限后，会立即重新调度已有等待请求；降低上限保留当前计数，等在途降到新上限以下再放行。
保存不重置已有会话和缓存绑定，不中断输出流；已排队请求的等待预算、已有绑定和冷却期限不追溯修改。
新会话使用新的保留窗口。Loomy 积分耗尽仍等到 UTC+8 次日零点，不使用普通限流冷却区间。

保存值位于 `<CODEARTS2API_HOME>/scheduling.json`（权限 `0600`），重启后继续生效。
优先级是 **界面保存值 > 环境变量 > 程序默认值**；未通过界面修改的项目仍读取环境变量。
完整账号备份不包含该宿主配置，迁移实例时需单独保留此文件；损坏配置会在启动时明确报错。
读写接口 `GET /admin/scheduling/api`、`PATCH /admin/scheduling/api/:provider` 均受管理鉴权保护。

### 多把调用方 Key（分组授权）

默认只有一把网关 Key。要「按人发 Key、按人限模型、按人看用量」时，用顶栏「调用方」页：

- **一把 Key 一个人**，可单独停用 / 删除；
- **分组决定能调哪些模型**（白名单）；
- **用量按人按模型记账**，只记元数据，不落 prompt / 回复正文。

在「分组」页建分组、勾白名单，在「Key」页新建并发给对方（明文只显示一次）。
`<home>/caller-keys.json` 不存在时该功能不生效，删掉即回滚。

## API

### HTTP 接口

| 路径                                                                | 说明                                             |
| ------------------------------------------------------------------- | ------------------------------------------------ |
| `GET /admin`                                                        | 管理界面（登录页 → 默认「总览」；渠道页复用上游 Jet Hub） |
| `POST /api/jet-hub`                                                 | Jet Hub 管理 RPC（上游实现原样透传，需管理密钥） |
| `GET /v1/models`、`POST /v1/chat/completions`、`POST /v1/responses` | OpenAI 兼容接口（上游网关，需网关 Key）          |
| `GET /healthz`                                                      | 健康检查（不含密钥，可给监控用）                 |

### 鉴权

两把钥匙，别混用：

| 密钥         | 位置                            | 给谁       | 权限                             |
| ------------ | ------------------------------- | ---------- | -------------------------------- |
| **管理密钥** | `<home>/admin-key`              | 只有你自己 | 进后台、改配置、导出全部账号凭据 |
| **网关 Key** | `<home>/openai-gateway/api-key` | 调用方     | 只能调 `/v1/*` 推理接口          |

脚本 / curl 直接带 `Authorization: Bearer <admin-key>` 访问 `/api/jet-hub`。

### OpenAI 兼容接口

登录 `/admin` → 页头「网关」按钮 → 拿实际地址、API Key 与模型清单。客户端把 `base_url`
指向网关、`api_key` 填网关 Key。模型 ID 形如 `provider/模型名`（如
`codearts/deepseek-v4.1-flash`），**必须带渠道前缀**，可用模型以 `GET /v1/models` 为准。
支持 SSE 流式与 base64 内联图片输入。

### 聚合路由

| 路由                     | 行为                                                                     |
| ------------------------ | ------------------------------------------------------------------------ |
| `aggregate/<规范模型名>` | 把同一模型在各渠道的条目归一化，按额度临期顺序选号，失败时切换下一个候选 |
| `jet-hub-auto/auto`      | 在候选渠道中自动挑选可用者与模型                                         |

需先配置好对应渠道的账号，否则目录为空；可在 `/admin` 的「聚合 (跨渠道)」面板设置轮换。
